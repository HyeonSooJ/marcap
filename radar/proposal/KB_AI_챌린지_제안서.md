# 마캡레이더 2.0 — 밈스탁 버블 확산 조기경보 & 맞춤형 투자자 보호 에이전트

> KB AI 챌린지 제안서 (2026)

## 0. 한 줄 요약

감염병이 사람 사이에 퍼지듯 특정 종목에 대한 "시장의 관심"도 확산된다는 관점에서,
역학(epidemiology)의 실효재생산수(Rt) 개념을 marcap 시가총액 데이터와 검색량·뉴스
데이터에 적용해 종목별 관심 확산 단계를 진단하고, 사용자의 투자 성향과 결합해
개인화된 위험 경고를 제공하는 서비스.

---

## 1. 문제 정의 및 필요성

### 1-1. 문제 상황

- 2026년 상반기 코스닥 급락 국면에서, 화제성에 이끌려 뒤늦게 진입한 개인투자자들이
  큰 손실을 입는 사례가 반복적으로 보도되었다. 관리종목 지정, 신용등급, 증권사 위험고지
  같은 기존 경고 장치는 대부분 재무·신용 지표를 근거로 "이미 위험해진 뒤"에야
  작동하며, 이런 정보는 이미 시장에 흔하다.
- 반면 "지금 이 종목에 대한 시장의 관심이 얼마나 빠르게, 어느 국면까지 번졌는가"는
  기존 위험 지표들이 다루지 않는 축이다. 화제성 종목(밈스탁)의 특징은 재무 악화가
  아니라 "관심의 확산과 소멸"이 주가를 움직인다는 데 있는데, 이를 정량적으로
  진단해주는 서비스는 마땅치 않다.
- 개인투자자, 특히 정보 습득이 늦은 투자자일수록 관심이 이미 정점을 지난 시점에
  뒤늦게 진입하는 경향이 있다(marcap 백테스트로 실증, 7절 참고). 문제는 "위험을
  모른다"가 아니라 "지금이 확산의 어느 단계인지 판단할 방법이 없다"는 것이다.

### 1-2. 문제를 겪는 주체

| 주체 | 겪는 문제 |
|---|---|
| 개인투자자(특히 2,30대 초보 투자자) | 화제성 종목에 뒤늦게 진입해 고점에 물리는 패턴 반복 |
| 증권사 리스크관리팀 | 재무/신용 지표만으로는 밈스탁형 변동성을 설명·경고하기 어려움 |
| 금융소비자보호 관점의 금융사(KB 등) | 투자자 보호를 위한 조기 경고 수단은 필요하나, 특정 종목 매매를
  추천하는 방식은 규제(무인가 투자자문) 리스크가 있어 활용이 제한적 |

### 1-3. 기존 대안과의 차별성

| 비교 대상 | 하는 일 | 한계 |
|---|---|---|
| 관리종목·투자주의환기종목 지정 | 재무/거래 이상을 사후 지정 | 이미 위험해진 뒤에야 작동, 밈스탁 특유의 관심 확산은 미반영 |
| 증권사 위험고지·신용등급 | 재무비율 기반 위험 등급 | 정보가 시장에 이미 흔함, "언제" 위험한지(타이밍)는 설명 못함 |
| 로보어드바이저·종목 추천 서비스 | 포트폴리오 배분/추천 | 무인가 투자자문 규제 리스크, 개인화가 성향이 아닌 상품 중심 |
| **본 제안 (마캡레이더 2.0)** | 시장 관심의 **확산 속도**를 역학모델로 진단 + **투자자 개인 성향**과 결합한
  위험 정보 제공 | — |

차별점은 세 가지다.

1. **다른 축의 신호**: 재무·신용 지표가 아니라 "정보 확산의 속도"라는, 기존 위험
   지표들이 다루지 않는 축으로 밈스탁 리스크를 진단한다. 감염병 확산모델(SIR)의
   실효재생산수(Rt) 개념을 시장 관심 확산에 이식하는 방법론 자체가 기존
   재무지표 기반 접근과 근본적으로 다르다.
2. **매매 추천이 아닌 위험 정보 제공**: "사라/팔아라"가 아니라 "지금 이 종목은
   확산의 어느 단계"라는 정보와, 그것이 "당신의 투자 성향에서는 왜 특히 주의가
   필요한지"를 설명한다. 무인가 투자자문 리스크를 구조적으로 피하면서도
   실질적인 투자자 보호 기능을 한다.
3. **개인화**: 동일한 확산 진단이라도 사용자의 행동 성향(물타기형/추격매수형/
   장기보유형)에 따라 위험도의 의미가 다르다는 점에 착안해, 5문항 설문으로
   성향을 태깅하고 진단과 결합한 맞춤 경고를 생성한다.

## 2. 구현 프로세스의 구체성 (입력 → 처리 → 출력)

```
[입력]
  ① marcap 일별 데이터 (거래대금, 시가총액, 등락률 등)
  ② 네이버 데이터랩 검색량 (종목명 검색 추이)
  ③ 네이버 뉴스 언급량
  ④ 사용자 투자 성향 설문 응답 (5문항)

        ↓

[처리 — 4단계 파이프라인]
  1단계 통계적 이상탐지 (anomaly_detector.py, 기존 마캡레이더 엔진 재사용)
     - 거래량/등락률/시가총액변화/순위변동의 60일 롤링 z-score로 1차 스크리닝
     - 확산모델은 "상대적 성장률"만 보기 때문에 평범한 종목에도 자주 반응한다
       (삼성전자 등으로 검증 시 오탐률 73%). 그래서 절대적으로 이례적인 종목만
       1차로 걸러낸 뒤에만 2단계를 적용해 오탐을 통제한다.

  2단계 SIR 확산 진단 (diffusion_model.py)
     - 거래대금 회전율(하락일 패닉매도는 제외) + 검색량을 결합해 관심도 지수 I(t) 산출
     - 지수증가 모델 I(t)≈I(0)e^(rt)에서 성장률 r을 롤링 로그선형회귀로 추정,
       세대기간 가정을 통해 실효재생산수 Rt=e^(r·generation_time)로 환산
     - Rt와 최근 고점 대비 위치로 4단계 분류: 평시 / 초기 확산기 / 포화기 /
       정점 지나 하락기

  3단계 투자 성향 태깅 (investor_profile.py)
     - 5문항 규칙 기반 설문으로 물타기형/추격매수형/장기보유형 3유형 분류
     - 전체 매매이력 분석 같은 무거운 방식 대신, 데모·MVP 범위에 맞게 의도적으로
       가벼운 설문 방식을 채택 (범위를 좁혀 완성도를 확보하는 트레이드오프)

  4단계 LLM 개인화 경고 생성 (llm_report.py)
     - 확산 진단 결과 + 투자 성향을 Claude에 전달해 "왜 이 사용자에게 지금 이
       종목이 주의가 필요한지"를 3~4문장으로 설명
     - 시스템 프롬프트에 "매수/매도 지시 금지, 완곡한 표현 사용, 확산 진단의
       방법론적 한계 인지" 규칙을 명시해 투자자문화·과신 위험을 통제
     - ANTHROPIC_API_KEY 미설정 시에도 규칙 기반 대체 문구로 저하 없이 동작
       (기존 마캡레이더의 "단계적으로 기능이 줄어드는" 설계 원칙 계승)

        ↓

[출력]
  - Streamlit 대시보드 신규 탭("밈스탁 확산 진단 + 맞춤 경고"): 확산 단계 표,
    종목 선택, 설문, 맞춤 경고 메시지
  - 데일리 리스크 브리핑에 확산 단계 진단 자동 포함 (기존 파이프라인 확장)
```

### 시스템 구성도 (텍스트)

```
marcap 데이터(자동 일일 갱신) ──┐
                                ▼
                       이상탐지 엔진(z-score) ──▶ 1차 스크리닝 종목
                                                        │
        네이버 데이터랩 검색량 ──┐                       ▼
        네이버 뉴스 언급량 ─────┴──▶ SIR 확산 진단 (Rt, 4단계 분류)
                                                        │
        사용자 투자 성향 설문 ──────────────────────────┤
                                                        ▼
                                        LLM(Claude) 개인화 경고 생성
                                                        │
                                                        ▼
                                Streamlit 대시보드 / 데일리 리포트
```

## 3. 데이터 활용 계획의 타당성

| 데이터 | 출처 | 확보 방법 | 비용 | 결합 방식 |
|---|---|---|---|---|
| 일별 거래대금/시가총액/등락률 | marcap 데이터셋(본 저장소) | 이미 확보, 매일 자동 갱신 중 | 무료 | 관심도 지수·1차 이상탐지 |
| 종목명 검색량 추이 | 네이버 데이터랩 검색어트렌드 API | 개발자센터 애플리케이션 등록 | 무료(일 1,000회, 로컬 캐싱으로 절약) | Rt 추정 입력 |
| 뉴스 언급량 | 네이버 뉴스 검색 API | 동일 애플리케이션에 권한 추가 | 무료(일 25,000건) | 보조 확산 신호, 원인 해설 |
| 전자공시 | OpenDART API | 회원가입 후 즉시 발급 | 무료 | 원인 해설 근거 |

모든 데이터가 무료 공개 API이며, 검색량 API는 쿼터가 낮아(일 1,000회) 동일
종목·구간 재조회를 로컬 parquet 캐시로 흡수하도록 설계했다 — 백테스트처럼 반복
조회가 많은 워크로드에서도 쿼터 소진 없이 재현 가능하다.

## 4. AI/LLM 활용 계획의 적절성

- **사용 모델**: Claude (Anthropic API)
- **활용 목적**: (1) 정량 진단(SIR Rt·단계)과 정성 맥락(뉴스·공시)을 결합한 원인
  해설, (2) 동일 진단이라도 사용자 성향에 따라 의미가 다르다는 점을 반영한
  개인화 경고문 생성. 통계/역학 모델이 잘하는 "정량 진단"과 LLM이 잘하는
  "맥락화·개인화 설명"을 역할 분리해 결합했다.
- **적용 과정**: 1차 이상탐지를 통과한 종목에 한해서만 LLM/검색량 API를 호출해
  비용을 통제한다. 시스템 프롬프트에 "매매 지시 금지 / 확산 진단의 근사치·한계
  인지 / 완곡한 표현 사용" 규칙을 명시해 투자자문화 위험과 과신을 통제한다.
- **한계와 보완**: SIR 진단은 실제 역학모델처럼 S·R 인구를 직접 관측하는 것이
  아니라 관심도 성장률로 Rt를 근사 역산한 것이며, 세대기간·임계값은 모델링
  가정이다(diffusion_model.py 모듈 docstring에 한계를 명시). 이 한계를
  숨기지 않고 LLM 프롬프트와 화면 문구에 그대로 노출해 사용자가 보조 지표로
  받아들이도록 설계했다.

## 5. 기대 효과 및 실제 활용 가능성

- **개인투자자 보호**: 화제성 종목에 뒤늦게 진입해 고점에 물리는 패턴을, 매매
  추천이 아닌 "확산 단계 정보 + 개인화 설명"으로 완화. 금융소비자보호라는
  KB의 방향성과 부합하면서도 무인가 투자자문 리스크를 피하는 구조.
- **KB 상품과의 연계 가능성**: 확산 후기·정점 단계로 진단된 종목에 대해 "지금은
  변동성이 큰 시기"라는 정보 제공에서 나아가, 분산투자·적립식 상품 등 KB의
  기존 안전자산형 상품 안내로 자연스럽게 연결 가능.
- **확장성**: 기존 마캡레이더의 데이터 파이프라인·백테스트 프레임워크를 그대로
  재사용해 구축했기 때문에, 검색량/뉴스 소스를 추가하거나 다른 시장경보
  이벤트로 백테스트 대상을 확장하는 데 추가 인프라 비용이 들지 않는다.

## 6. 예비 검증 결과 (백테스트)

아이디어 수준에 그치지 않고, marcap 실데이터로 SIR 확산 진단의 예측력을
검증했다. 방법: 이상탐지로 플래그된 종목·날짜에 대해 확산 단계를 진단하고,
그 시점 이후 N영업일 순방향 수익률을 단계별로 비교했다. 가설은 "초기 확산기로
진단된 시점 이후 수익률이 정점 지나 하락기로 진단된 시점 이후 수익률보다 평균적으로
높다"이다.

| 확산 단계 | 5일 순방향수익률(평균) | 20일 순방향수익률(평균) | 표본 수 |
|---|---|---|---|
| 초기 확산기 | **+0.71%** | -1.39% | 295건 |
| 포화기 | -5.17% | -0.78% | 32건 |
| 정점 지나 하락기 | **-2.73%** | **-7.20%** | 59건 |
| 평시 | -5.35% | -9.48% | 9건 |

가설대로 초기 확산기의 순방향 수익률이 정점 지나 하락기보다 5일·20일 기준 모두
뚜렷하게 높게 나타나, SIR 근사 진단이 단순 노이즈가 아니라 실제로 확산 국면을
구분해내고 있다는 예비 증거를 확인했다. 재현 가능한 스크립트:
`radar/scripts/backtest_diffusion.py`.

> 한계: 표본이 이상탐지로 1차 스크리닝된 종목(이미 이례적으로 움직인 종목)에
> 한정되어 있어, 임의의 종목에 일반화하기 전에는 추가 검증이 필요하다. 또한
> 검증 기간이 특정 구간에 한정되어 있어 다른 시장 국면에서의 재검증이 본선
> 단계의 개선 과제다.
