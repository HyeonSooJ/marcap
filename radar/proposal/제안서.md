# 마캡레이더(MarcapRadar) — 상장기업 이상변동 조기경보 & LLM 원인 해설 서비스

> KODATA·BDAI 공모전 제안서 초안 (예선)

## 0. 한 줄 요약

상장기업의 시가총액·주가·거래량 데이터를 매일 통계적으로 스캔해 "이상 변동"을 조기에
잡아내고, 공시·뉴스 데이터를 결합한 LLM이 "왜 이런 변동이 생겼는지"를 사람이 읽을 수 있는
리포트로 자동 설명해주는 리스크 모니터링 서비스.

---

## 1. 문제 정의 및 필요성

### 1-1. 문제 상황

- 코스피·코스닥 상장사는 2,800개가 넘고, 매일 이 중 일부가 급등락·거래량 급증·시가총액
  순위 급변동 등 이상 신호를 보인다. 이런 신호는 회계 부실, 미공개정보 이용, 작전세력 개입,
  M&A, 경영권 분쟁 등의 전조인 경우가 많지만 사람이 전 종목을 매일 모니터링하는 것은
  현실적으로 불가능하다.
- 한국거래소(KRX)는 투자주의·투자경고·투자위험종목 지정, 관리종목 지정, VI(변동성완화장치)
  같은 시장경보 제도를 운영하고 있지만, **"이상하다"는 신호(What)만 제공할 뿐 "왜
  이상한지"(Why)는 설명하지 않는다.** 그 원인을 찾는 것은 여전히 애널리스트·리스크
  관리자가 공시와 뉴스를 일일이 뒤져야 하는 수작업 영역으로 남아있다.
- 신용평가사의 재무비율 기반 부실예측모형(Altman Z-score류)은 분기·연간 재무제표에
  의존해 반응 속도가 느리고, 시장 데이터(가격·거래량)가 먼저 보내는 조기 신호를 포착하지
  못한다.

### 1-2. 문제를 겪는 주체

| 주체 | 겪는 문제 |
|---|---|
| 증권사 리스크관리팀 | 전 종목 실시간 모니터링 인력 부족, 이상신호 발견 후 원인 파악에 시간 소요 |
| 개인투자자 | 관리종목 지정 등 공식 위험신호가 뜨는 시점엔 이미 주가가 급락한 뒤인 경우가 많음 |
| 감사·감독기관(금감원 등) | 불공정거래 조사 대상 스크리닝을 위한 1차 필터링 도구 부재 |
| 기관투자자 | 보유 종목의 리스크를 매일 정성적으로 체크할 리소스 부족 |

### 1-3. 기업정보 데이터와의 관련성

marcap(시가총액) 데이터셋은 1995년부터 현재까지 전 상장종목의 일별 가격·거래량·시가총액·
시장구분·소속부(Dept, 관리종목/투자주의환기종목 지정 이력 포함) 데이터를 담고 있는
대표적인 기업정보 데이터다. 여기에 전자공시(DART), 뉴스 데이터를 결합해 시장 데이터
이면의 기업 이벤트를 해석하는 것이 본 제안의 핵심이다.

## 2. 아이디어의 창의성 및 차별성

| 비교 대상 | 하는 일 | 한계 |
|---|---|---|
| KRX 시장경보제도 | 사후적으로 "이상 종목"을 지정 | 원인 설명 없음, 사후 대응 |
| 증권사 시세 조회 서비스 | 가격/차트 조회 | 이상 여부 판단·설명 없음 |
| 신용평가사 부실예측모형 | 재무제표 기반 부실 예측 | 반응 속도 느림(분기 단위), 시장 신호 미반영 |
| **마캡레이더(본 제안)** | 일별 시장 데이터로 **선제 탐지** + **LLM이 공시·뉴스와 엮어 원인을 설명** | — |

차별점은 두 가지다.

1. **선제성**: 공식 위험 지정(관리종목/투자주의환기종목)보다 먼저 통계적 이상신호로
   포착한다. (아래 3번 검증 결과 참고)
2. **설명 자동화**: 단순 스코어링에 그치지 않고, LLM이 관련 공시·뉴스를 종합해 "무엇이
   이상한지 / 왜 그런지 / 근거가 있는지 없는지 / 리스크 등급"을 사람이 바로 읽을 수 있는
   문장으로 생성한다. 기존 단순 시세조회·경보 서비스와 달리, 결과를 해석하는 데 필요한
   전문성 장벽을 낮춘다.

## 3. 구현 프로세스의 구체성 (입력 → 처리 → 출력)

```
[입력]
  ① marcap 일별 데이터 (Date, Code, Name, Close, ChangesRatio, Volume, Marcap, Rank, Dept ...)
  ② DART 공시 목록 (종목별 최근 30일 공시 제목/일자/제출인)
  ③ 네이버 뉴스 검색 결과 (종목명 기준 최근 뉴스 제목/요약)

        ↓

[처리 — 3단계 파이프라인]
  1단계 통계적 이상탐지 (radar/src/anomaly_detector.py)
     - 종목별로 거래량, 등락률, 시가총액 변화율, 시총순위 변동을
       60거래일 롤링 z-score로 표준화
     - 4개 지표 중 최댓값을 종합 이상점수(AnomalyScore)로 산출
     - 임계값(기본 z≥3.0) 초과 종목을 일별 상위 N개(기본 10개) 선별

  2단계 컨텍스트 수집 (radar/src/dart_collector.py, news_collector.py)
     - 선별된 종목에 한해 DART 공시 목록·네이버 뉴스를 조회
       (전종목이 아닌 "플래그된 종목"만 호출 → API/LLM 비용 최소화)

  3단계 LLM 원인 해설 (radar/src/llm_report.py)
     - 이상탐지 결과 + 공시 목록 + 뉴스를 Claude에 프롬프트로 전달
     - "한줄요약 / 이상신호 내용 / 추정 원인(근거 구분) / 리스크 등급"
       4개 항목의 마크다운 리포트 생성
     - 근거 없는 단정을 금지하는 규칙을 시스템 프롬프트에 명시해 환각 위험을 통제

        ↓

[출력]
  - 데일리 리스크 브리핑 (마크다운 리포트, radar/output/reports/YYYY-MM-DD.md)
  - 웹 대시보드 (Streamlit, radar/app.py) — 오늘의 이상신호 스캔, 리포트 열람,
    백테스트 성능 지표 확인
  - GitHub Actions로 매일 자동 실행·자동 커밋 (기존 marcap 데이터 자동 업데이트
    파이프라인 직후 트리거)
```

### 시스템 구성도 (텍스트)

```
marcap 데이터(자동 일일 갱신)
        │
        ▼
 이상탐지 엔진(z-score) ──▶ 상위 N개 종목 선별
        │
        ▼
 DART 공시 API / 네이버 뉴스 API (선별 종목만 호출)
        │
        ▼
 LLM(Claude) 원인 해설 생성
        │
        ▼
 데일리 리포트(.md) ──▶ Streamlit 대시보드 / GitHub 자동 커밋
```

## 4. 데이터 활용 계획의 타당성

| 데이터 | 출처 | 확보 방법 | 비용 | 결합 방식 |
|---|---|---|---|---|
| 일별 시가총액/주가/거래량 | marcap 데이터셋(본 저장소) | 이미 확보, 매일 자동 갱신 중 | 무료 | 이상탐지 핵심 입력 |
| 관리종목/투자주의환기종목 지정 이력 | marcap `Dept` 컬럼 | 이미 확보 | 무료 | 백테스트 정답 레이블 |
| 전자공시 목록 | OpenDART API | 회원가입 후 API 키 즉시 발급 | 무료 | 이상신호 원인 후보 |
| 뉴스 | 네이버 검색 오픈API | 개발자센터 애플리케이션 등록 | 무료(일 25,000건 한도) | 이상신호 원인 후보 |

모든 데이터가 **회원가입만으로 확보 가능한 무료 공개 API**이며, 별도의 기업 제휴나 유료
데이터 구매가 필요 없다. marcap 데이터셋은 이미 본 저장소에서 1995년부터 매일 자동
수집되고 있어 별도 수집 인프라 구축 비용이 들지 않는다.

## 5. AI/LLM 활용 계획의 적절성

- **사용 모델**: Claude (Anthropic API)
- **활용 목적**: 정형 데이터(이상탐지 스코어)와 비정형 데이터(공시 제목, 뉴스 텍스트)를
  결합해 사람이 이해할 수 있는 원인 해설 리포트로 변환. 통계 모델이 잘하는 "이상 탐지"와
  LLM이 잘하는 "맥락 해석·요약"을 역할 분리해 결합했다.
- **적용 과정**: 이상탐지로 선별된 종목에 한해서만 LLM을 호출해 비용을 통제하고
  (전종목 대비 API 호출량을 90% 이상 절감), 시스템 프롬프트에 "근거 없는 단정 금지
  / 투자 조언 금지 / 확인 안 된 경우 명시" 규칙을 넣어 환각·과신 리스크를 관리한다.
- **한계와 보완**: LLM 리포트는 참고 자료이며 최종 판단은 사람이 하도록 매 리포트에
  디스클레이머를 포함한다.

## 6. 기대 효과 및 실제 활용 가능성

- **증권사/자산운용사 리스크관리팀**: 전종목 수작업 모니터링을 대체하는 1차 스크리닝
  도구로 활용, 애널리스트의 원인 조사 시간을 단축
- **개인투자자**: 관리종목 지정 등 공식 경보가 뜨기 전 조기 참고 정보로 활용해 대응 시간 확보
- **감독기관**: 불공정거래·부실 징후 스크리닝의 1차 필터로 확장 가능
- **오픈소스 확장성**: marcap 저장소 자체가 커뮤니티에 공개된 데이터셋이므로, 본 서비스도
  같은 방식으로 공개해 누구나 검증·기여할 수 있는 구조로 설계

## 7. 예비 검증 결과 (백테스트)

아이디어 수준에 그치지 않고, **기존 marcap 데이터만으로 조기경보 가설을 실제로
검증**했다. 2022-01-01 ~ 2026-07-01 기간 동안 관리종목/투자주의환기종목으로 신규
지정된 전체 이벤트를 대상으로, 지정일 이전 20영업일 구간에서 이상탐지 모델이 사전에
신호를 잡아냈는지 백테스트했다.

| 지표 | 결과 |
|---|---|
| 검증 기간 | 2022-01-01 ~ 2026-07-01 (약 4.5년) |
| 위험지정 이벤트 수 | 368건 |
| 조기탐지 커버리지 | **55.4%** (지정 20영업일 전부터 사전 포착) |
| 평균 리드타임 | **11.8 영업일** |

재현 가능한 스크립트: `radar/scripts/backtest.py` (본 저장소에 포함, 실행 시 동일 결과
재현 가능)

> 참고: 현재 모델은 가격·거래량 기반 통계 지표만 사용한 베이스라인이며, 향후 공시·뉴스
> 텍스트 피처를 탐지 단계에도 결합하면 커버리지·리드타임 개선 여지가 있다. 이는 본선
> 구현 단계의 개선 과제로 제시한다.
